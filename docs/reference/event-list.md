# Event list

Every event class lives in `bostie.events`. Listen to one with `@bot.listen`, as the [events guide](../guide/events.md) explains. The intents column names the intents Discord needs to send the event, any one of them enough; an empty cell means Discord sends it without an intent, or only as the answer to a request. Every gateway event also has `shard_id`, `raw_json` and `raw`. The [API reference](api/events.md) has every field with its type.

## Events of the bot

These come from bostie, not from Discord; their names are bostie's own.

| Event | Name | Fields | Sent when |
|---|---|---|---|
| `Starting` | `bot.starting` | | `start()` is about to sync and connect; REST works |
| `Started` | `bot.started` | | every shard is ready, once per `start()` |
| `Stopping` | `bot.stopping` | | `close()` began after `Started`; the gateway is still open |
| `Stopped` | `bot.stopped` | | `close()` finished; the gateway and REST are gone |
| `ShardReady` | `shard.ready` | `shard_id` | a shard's new session is ready and its guilds arrived |
| `ShardDisconnect` | `shard.disconnect` | `shard_id`, `code`, `reason`, `resuming` | a shard lost its connection |
| `ShardStop` | `shard.stop` | `shard_id`, `code`, `reason` | a shard stopped for good |
| `ShardBackpressure` | `shard.backpressure` | `shard_id`, `queued_bytes` | a shard paused reading because the event loop falls behind |
| `ListenerError` | `bot.listener_error` | `listener`, `event`, `error` | a listener raised |
| `TaskError` | `bot.task_error` | `task`, `error` | a background task raised |
