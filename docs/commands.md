# Commands and components

- `checks=[...]` on a command, group, subcommand or route, and `@router.check` for all of a router's, run before the handler, the bot's first: a function of the context returns or awaits whether the handler may run. `bostie.checks` has `has_permissions(...)`, `bot_has_permissions(...)` (the bot's permissions in that channel, as the interaction carries them), `Cooldown(rate, seconds, per="user")` and `MaxConcurrency(number, per="global")`. A refusal raises a `CheckFailure`, such as `MissingPermissions` or `CooldownActive` with its `retry_after`, which reaches the error hooks; without one, the user gets its message as an ephemeral answer.
- `@bot.on_error`, `@router.on_error(SomeError)` and `@command.on_error` register `async def hook(ctx, error)` for what a handler raises, as [Errors](errors.md) describes. `@router.before_invoke` and `@router.after_invoke` run `async def hook(ctx)` around each handler of the router, the bot's outermost, and after hooks run even when the handler raised.
- Options come from the type hints: `str`, `int`, `float`, `bool`, `User`, `ResolvedMember`, `PartialChannel`, `Role`, `Attachment` and `User | Role`. `Range[int, 2, 100]` bounds a number or a string's length, a string in `Annotated` is the description, a default or `| None` makes the option optional, a `Literal`, an `Enum` or `Option(choices=...)` gives choices, and `Option(file_types=["image", ".pdf"])` limits what an `Attachment` option takes. `Annotated[Color, Convert(parse)]` hands the handler what `parse(ctx, value)` returns, sync or async, and the option takes the type of `parse`'s value parameter.
- `@bot.entry_point("Launch")` handles the entry point command that opens an app's Activity from the App Launcher, and syncs it in place of the one Discord made. `await ctx.launch_activity()` opens the Activity from that or any other context. The entry point is global, so `dev_guilds` leaves it out.
- `name_localizations={"fr": "lancer"}` and `description_localizations=` on a command, group or subcommand, the same on an `Option`, and `Choice(..., name_localizations=)` show those texts to users of that language. `Option(choices=...)` listing the values of a `Literal` or an `Enum` in order relabels and localizes its choices.
- `@bot.user_command` and `@bot.message_command` add a command to the context menu of a user or a message. The handler takes the target after the context, typed `User` or `ResolvedMember`, or `Message`, `WebhookMessage` or both.
- `ctx.modal(ui.modal(...))` opens a form from a command or a component. `@bot.on_modal` routes its submit by custom id template, like a component, and `ctx.text`, `ctx.values`, `ctx.ids`, `ctx.users`, `ctx.members`, `ctx.roles`, `ctx.channels`, `ctx.attachments`, `ctx.choice` and `ctx.checked` read the answers by their custom ids: `ctx.values` gives the options picked as strings, `ctx.ids` the users, roles, channels or uploads picked as ids, and the others what those ids resolve to.
- A select on a message gives the same through `ctx.values`, `ctx.ids`, `ctx.users`, `ctx.members`, `ctx.roles` and `ctx.channels` of its `ComponentContext`.
- Messages use [Components V2](https://docs.discord.com/developers/components/overview): `ui.text`, `ui.section`, `ui.container`, `ui.media_gallery`, `ui.file` and `ui.separator` build them, and bostie sets the `IS_COMPONENTS_V2` flag for you. Such a message cannot also carry content, embeds, stickers or a poll, and bostie raises `ValueError` before sending one.
- `ui.premium_button(sku_id)` offers one of the app's SKUs for sale, and every component builder takes an `id=`. The builders raise `ValueError` for what the docs' limits rule out, such as a sixth button in a row or a modal title over 45 characters.
- `@bot.on_component(template, ephemeral=True, auto_defer=1.0)` and the same on `@bot.on_modal` set how a route's answers and automatic defer go, as `@bot.command(...)` does for a command. Without them, the router's defaults apply, then public answers and the bot's `auto_defer`.
- `ctx.edit(followup.id, ...)`, `ctx.fetch(followup.id)` and `ctx.delete(followup.id)` reach a follow-up, and without an id the original answer. An interaction of an app installed only to the user takes 5 follow-ups, and a sixth logs a warning.
- `press = await bot.wait_for_component(custom_id, check=...)` waits inside a handler for the next use of a component and returns its context, ready to answer, for prompts such as a confirmation; `bot.wait_for_modal` does the same for a modal submit. No route runs for what a wait takes. Bound the wait with `asyncio.timeout()`, and on `TimeoutError` edit the message to drop or disable its buttons.
- Custom id templates such as `reroll:{sides:int}` are parsed into typed handler arguments, and `reroll.id(sides=6)` builds a matching id, so buttons keep working after a restart. `ui.pager(route, page, count)` builds previous and next buttons around "2 / 5" for a route whose template has `{page:int}`, for paged messages: the route renders the page it gets and `ctx.update`s the message.
