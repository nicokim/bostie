# Приём и запись

## Форматы { #formats }

`vc.receive(format)` возвращает `voice.Receiver` для `voice.ReceiveFormat`:

| `vc.receive(format)` | Элементы | Для чего |
|---|---|---|
| `voice.PCM(rate=48000, channels=2, sample="s16le")` | объекты `Frame` с декодированными отсчётами в этом формате; частота — одна из `voice.DECODE_RATES`: 8, 12, 16, 24 или 48 кГц | прослушивание, распознавание речи, уровни |
| `voice.Opus()` | объекты `Frame`, чьё `data` — один пакет Opus | запись или пересылка без декодирования |
| `voice.Packets()` | объекты `Packet`, расшифрованные, в порядке прихода, до джиттер-буфера | собственный джиттер-буфер, расширения заголовка RTP |

У `Frame` есть `user_id`, `ssrc`, RTP-`timestamp`, `offset` и `samples` по часам приёмника 48 кГц, `received_at`, `data`, `lost` (истина для звука, который Opus досочинил, чтобы скрыть потерянный пакет), а для PCM — `level`, среднеквадратичный уровень кадра в dBFS. Часы запускаются при открытии приёмника, поэтому кадры разных пользователей выравниваются по `offset`. У `Packet` есть `user_id`, `ssrc`, `sequence`, `timestamp`, `received_at`, полезная нагрузка `opus` и расширения заголовка RTP `extensions`.

## Кого слушать { #choosing-whom-to-hear }

- `users=[...]` оставляет только этих пользователей, а `exclude=[...]` исключает некоторых.
- `include_self=True` добавляет собственный звук бота.
- `mix=True` (PCM и Opus) выдаёт один поток, в котором смикшированы все, с `user_id`, равным `None`.
- `markers=True` вставляет между кадрами события `SpeechStart`, `SpeechStop` и `UserLeave`, каждое со своим `offset` по тем же часам, так что потребитель знает, где речь начинается и заканчивается, не замеряя время сам.

## Настройки { #settings }

`vc.receive` принимает эти именованные аргументы; у `Packets()` нет джиттер-буфера, поэтому он не принимает `jitter`.

| Настройка | По умолчанию | Значение |
|---|---|---|
| `buffer` | `Defaults.receive_buffer`, 2.0 | сколько секунд элементов приёмник держит для медленного потребителя, от 0,02 до 60 |
| `overflow` | `Defaults.overflow`, `"drop_oldest"` | что делать, когда буфер заполнен: отбрасывать самые старые элементы или `"drop_newest"` |
| `jitter` | `Defaults.jitter`, 0.1 | сколько секунд ждать опоздавшие пакеты, прежде чем играть дальше, от 0 до 1; только PCM и Opus |
| `stall` | `Defaults.receive_stall`, `"wait"` | что делать при переподключении: `"wait"` оставляет приёмник открытым, `"end"` завершает его |

## Чтение { #reading }

`async for item in rx` ждёт элементы и останавливается, когда приёмник завершается. `async with rx:` закрывает его в конце блока.

- `rx.get_nowait()` возвращает следующий элемент или вызывает `voice.Empty`, если очередь пуста, и `voice.ReceiverClosed`, если приёмник завершился.
- `rx.queued` — сколько ждёт самый старый элемент в очереди: отставание потребителя.
- `rx.clear()` отбрасывает всё, что стоит в очереди, и продолжает в реальном времени.
- `await rx.mark()` возвращает `True`, как только звук, полученный до вызова, поставлен в очередь или отброшен, или `False` через 1,2 секунды плюс удвоенный джиттер; отмена одного ожидания оставляет метку для остальных.
- `rx.stats()` возвращает `ReceiverStats`: элементы доставленные (`delivered`), отброшенные при переполнении (`dropped`) и пакеты, потерянные по пути (`lost`).
- `rx.close()` прекращает приём. `rx.closed_reason`, `voice.ClosedReason`, говорит, почему приёмник завершился: `CLOSED`, `DISCONNECTED`, `MOVED` (бот сменил канал) или `RECONNECTING` (при `stall="end"`).

Модератор может отключить боту звук, и тогда Discord не присылает ему никакого звука; bostie пишет предупреждение в лог, когда приёмник открывается при отключённом у бота звуке и когда боту отключают звук при открытых приёмниках.

## Речь { #speech }

Определение речи работает на Rust в каждом подключении, пока включён `speech_activity`: пользователь начинает говорить со своим первым звуком и перестаёт после `speech_hangover` секунд тишины, по умолчанию 0,2. `vc.speaking` хранит, кто говорит сейчас, события `SpeechStart` и `SpeechStop` сообщают об этом слушателям, а приёмники, открытые с `markers=True`, несут это в своём потоке. Если `speech_activity` выключен и ни один приёмник не открыт, bostie даже не расшифровывает входящий звук.

`voice.utterances(rx, min_silence=0.8, max_length=30.0)` группирует кадры приёмника PCM в объекты `Utterance`: речь одного пользователя от начала до конца, с `data` в формате приёмника, её `offset`, `duration` и потерянными секундами `lost`. Высказывание заканчивается после `min_silence` секунд без речи или на `max_length` секундах. Для этого нужен приёмник PCM без `mix`, открытый с `markers=True`, или `level` в dBFS, который тогда вместо маркеров решает, что считать речью.


`voice.Recorder(vc, path)` записывает каждого пользователя в отдельный файл или, с `mix=True`, весь звонок в один. Путь — это шаблон с `{guild_id}` и `{user_id}`: шаблон обязателен для отдельного файла на пользователя и не допускается с `mix=True`, а расширение выбирает контейнер:

- `.ogg` или `.opus` пишет Ogg Opus. Для каждого пользователя полученные пакеты Opus пишутся как есть, без декодирования.
- `.wav` пишет PCM 16 бит в формате рекордера `format`, по умолчанию стерео 48 кГц; его частота — одна из `voice.DECODE_RATES`.

С `align=True` (по умолчанию) промежутки заполняются тишиной, так что каждый файл начинается с момента начала записи и файлы выравниваются между собой. `users`, `exclude` и `include_self` выбирают, кого записывать, как и для приёмника, а `buffer` (30 секунд) и `jitter` (0,3 секунды) больше, чем значения по умолчанию у приёмника, потому что диск может подтормаживать. Запись заканчивается сама через `max_duration` секунд, или когда её файлы достигают `max_size` байт, или когда завершается подключение.

`await recorder.stop()` завершает запись, как только уже услышанный звук записан, и возвращает файлы в виде словаря из ID пользователя в `Path`, где ключ смикшированного файла — `None`. `await recorder.wait()` ждёт, пока запись закончится сама. `recorder.files` перечисляет записанные на данный момент файлы, а `recorder.stats()` — счётчики приёмника, где `dropped` означает, что диск отставал дольше, чем на `buffer`.
