# Синки и сырой звук

Синк — это ограниченный буфер, в который Python пишет звук, а микшер на Rust читает его порциями по 20 мс. Каждый трек и каждая очередь играют через синк. ## Форматы { #formats }

`vc.sink(format)` возвращает `voice.Sink` для того, что вы будете писать, — `voice.Format`:

- `voice.PCM(rate=48000, channels=2, sample="s16le")`: чередующиеся отсчёты little-endian, `"s16le"` (16-битные целые) или `"f32le"` (32-битные числа с плавающей точкой), моно или стерео, от 8000 до 192 000 Гц. bostie пересэмплирует в 48 кГц на Rust; частота должна делить 48 кГц на блоки не больше 960 отсчётов, что выполняется для всех распространённых частот.
- `voice.Opus()`: один пакет Opus на запись. Пакеты по 20 мс, 48 кГц стерео отправляются как записаны, пока синк играет один, с громкостью 1 и без фильтров; всё остальное декодируется и микшируется.

`voice.OpusEncoder(pcm_format, encoder=EncoderSettings())` кодирует PCM в такие пакеты в процессе Python — для звука, который вы хотите закодировать один раз и отправить во много синков: `encode(data)` возвращает все готовые на данный момент пакеты, а `flush()` дополняет остаток тишиной. Его битрейт по умолчанию — 64 кбит/с, поскольку ему не за каким каналом следовать.

## Запись { #writing }

- `await sink.write(data)` ставит звук в очередь и ждёт, пока в синке уже лежит `buffer` секунд. Это ожидание и есть обратное давление, которое держит ваш источник данных в темпе реального времени.
- `sink.write_nowait(data)` ставит в очередь всю порцию сразу или вызывает `BufferFull`.
- `async with sink:` в конце блока ждёт, пока всё записанное проиграется, а затем закрывает синк; исключение в блоке вместо этого отбрасывает то, что стоит в очереди.
- `await sink.drain()` ждёт, пока проиграется всё записанное на данный момент; `False`, если часть была отброшена.
- `sink.clear()` отбрасывает то, что стоит в очереди; `clear(until=marker)` — только часть до маркера, `clear(since=marker)` — только часть после него.
- `sink.close()` отбрасывает то, что стоит в очереди, и закрывает синк. Запись в закрытый синк вызывает `SinkClosed`.

`sink.mark()` возвращает `Marker`, стоящий после записанного на данный момент звука. `await marker` возвращает `True`, когда весь звук до него проигран, или `False`, если часть была отброшена раньше; `marker.done` говорит, известно ли это уже. С помощью маркеров плеер узнаёт, когда трек действительно закончился, а не просто был записан.

## Настройки { #settings }

`vc.sink` принимает эти именованные аргументы; `vc.play` и `voice.Queue` тоже принимают `buffer` и `stall`.

| Настройка | По умолчанию | Значение |
|---|---|---|
| `buffer` | `Defaults.sink_buffer`, 0.2 | сколько секунд синк держит, прежде чем `write` начнёт ждать, от 0,02 до 60 |
| `stall` | `Defaults.stall`, `"hold"` | что делать, когда звук нельзя отправить, — во время переподключения или перехода DAVE: `"hold"` сохраняет его, чтобы проиграть потом, `"drop"` отбрасывает его в реальном времени — для живого звука, который не должен отставать |
| `volume` | 1.0 | умножает отсчёты; `sink.volume` меняет его во время воспроизведения |
| `filters` | `Filters()` | [эффекты](playback.md#volume-and-filters); `sink.filters` меняет их во время воспроизведения |
| `after` | `None` | другой синк этого подключения; этот молчит, пока тот не закроется или не доиграет то, что было записано до его последнего `drain()` |
| `crossfade` | 0.0 | вместе с `after` — на сколько секунд раньше начать и сделать плавный переход; синк тогда буферизует на столько же больше |

`after` и `crossfade` — это то, как очередь играет без пауз: синк следующего трека заполняется, пока играет текущий, и подхватывает воспроизведение точно с нужного отсчёта.

## Состояние и счётчики { #state-and-counters }

`sink.queued` — сколько секунд звука ждёт в очереди, `sink.passthrough` — ушёл ли последний пакет так, как был записан, а `sink.closed` — закрыт ли синк. `sink.stats()` возвращает `SinkStats`:

| Поле | Значение |
|---|---|
| `sent` | сколько секунд звука отправлено |
| `position` | позиция воспроизведения в секундах, как её отсчитывают маркеры |
| `underruns` | сколько раз синк опустел во время воспроизведения вне `drain()`: источник данных отстал |
| `held_ticks` | сколько тактов синк удерживался, потому что звук нельзя было отправить |
| `dropped` | сколько секунд отброшено при остановке с `"drop"` |
| `passthrough_packets` | сколько пакетов отправлено как записано, без декодирования |

Главное, за чем стоит следить, — опустошения (`underruns`): источник данных, который не успевает держаться на `buffer` секунд впереди, слишком медленный, или заблокирован цикл событий. `vc.sinks` перечисляет открытые синки подключения.
