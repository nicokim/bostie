## Для чего она создана { #what-it-is-built-for }

### Голос { #voice }

С 1 марта 2026 года Discord принимает только звонки со сквозным шифрованием ([DAVE](https://docs.discord.com/developers/topics/voice-connections)). Голосовой движок bostie работает в потоках Rust, вне GIL: такт 20 мс, декодирование, микширование, кодирование Opus, транспортное шифрование и DAVE. Python нужно лишь держать буфер каждого синка заполненным — по умолчанию это 0,2 секунды звука. bostie проигрывает файлы, URL, потоки HLS и ваш собственный PCM или Opus, микширует несколько источников, принимает звук каждого говорящего отдельно и записывает звонки.

### Боты, которые переживают изменения Discord { #bots-that-survive-discords-changes }

Неизвестные поля, значения перечислений, типы компонентов и типы взаимодействий никогда не ломают декодирование. Каждое событие и каждая модель, декодированная из полной полезной нагрузки, хранят сырой JSON, а `bot.http` и слушатели сырых событий дают доступ к тому, что bostie ещё не моделирует.

### Типы, которые совпадают с документацией Discord { #types-that-match-discords-documentation }

Поле, которое Discord присылает всегда, никогда не бывает `None`, а у частичного объекта свой класс: участник, полученный из параметра команды, — это `ResolvedMember`, у которого нет `deaf` и `mute`.

### Команды из сигнатур { #commands-from-signatures }

Параметры, варианты, диапазоны и автодополнение берутся из аннотаций типов. Имена, описания, количество параметров и варианты проверяются на соответствие лимитам Discord в момент выполнения декоратора, а не тогда, когда Discord отклонит синхронизацию.

### Тесты без Discord { #tests-without-discord }

`bostie.testing.FakeDiscord` — локальный шлюз и REST API, на которых можно запускать вашего настоящего бота.
