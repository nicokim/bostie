# Регистрация команд

Discord показывает команду только после того, как приложение её зарегистрировало. bostie делает это за вас: при запуске бот сравнивает определённые вами команды с теми, что хранит Discord, и отправляет их, только если что-то отличается.

## Синхронизация при запуске { #the-sync-at-startup }

`bot.start()` и `bot.run()` выполняют синхронизацию до подключения к шлюзу. Для каждой области — глобальной или одного сервера — bostie получает зарегистрированные команды вместе с их локализациями, сравнивает их поле за полем и, если они отличаются, заменяет команды области одним запросом. В логе появляется `commands up to date (global)` или `commands synced (global): added [...], removed [...], changed [...]`.

Команда, которая есть в Discord, но которую вы больше не определяете, удаляется, если только её тип не из тех, что вы вообще не определяете: бот без `@bot.entry_point` сохраняет команду точки входа, которую Discord создал для его Активности.

`Bot(auto_sync=False)` пропускает синхронизацию. `await bot.sync_commands()` прямо сейчас заменяет команды каждой области, изменились они или нет, и возвращает по `SyncResult` на область с именами, которые были добавлены (`added`), удалены (`removed`) и изменены (`changed`), и с `ids`, которые Discord присвоил слэш-командам.

Команды могут иметь одно имя, если ни на одном сервере нет двух таких команд: глобальная `/rules` и `/rules` для одного сервера или по `/rules` на каждый сервер. Каждая регистрируется в своей области, а взаимодействие запускает команду, зарегистрированную на его сервере, а если такой нет — глобальную. На этом сервере Discord показывает и глобальную, и серверную команду. При `dev_guilds` собственная команда сервера занимает место глобальной на этом сервере. Две команды с одним именем, чьи серверы пересекаются, или две глобальные вызывают `CommandDefinitionError` при регистрации второй. Команды пользователя и сообщения подчиняются тем же правилам.

Синхронизация затрагивает только области, в которых есть команды. Если вы уберёте `dev_guilds`, команды останутся на тестовом сервере рядом с новыми глобальными; их удаляет `await bot.rest.commands.bulk_overwrite_guild(bot.application_id, guild_id, [])`.

## Где можно использовать команды { #where-commands-can-be-used }

`contexts` и `integration_types` действуют на глобальные команды. Задайте их на команде, роутере или боте:

- `contexts`: `InteractionContextType.GUILD`, `BOT_DM` (личные сообщения с ботом) и `PRIVATE_CHANNEL` (другие личные сообщения и групповые ЛС — для приложения, установленного пользователем).
- `integration_types`: `ApplicationIntegrationType.GUILD_INSTALL` и `USER_INSTALL`.

`Bot(contexts=[...], integration_types=[...])` задаёт значение по умолчанию для каждой глобальной команды, у которой нет собственного. Если они нигде не заданы, bostie не отправляет ни одно из этих полей, и Discord применяет свои значения по умолчанию; для `integration_types` это контексты установки, настроенные для приложения. Удаление настройки, которую вы задавали, считается изменением, поэтому следующая синхронизация снова даст команде значения Discord по умолчанию.

## Упоминания команд { #command-mentions }

`await bot.command_mention("roles color set")` возвращает `</roles color set:ID>`, что Discord показывает как кликабельную команду. Метод использует ID из последней синхронизации или один раз на область спрашивает Discord. С `guild_id=` команда, зарегистрированная на этом сервере, важнее глобальной с тем же именем. Неизвестное имя вызывает `LookupError`, а вызов до запуска бота — `StateError`. `fmt.command(name, command_id)` строит тот же текст из ID, который у вас уже есть.

## Когда Discord отклоняет команды { #when-discord-refuses-the-commands }

Синхронизация, которую Discord отклоняет с кодом 400, вызывает `CommandSyncError`. В его сообщении по строке на каждую проблему с именем команды, путём к параметру и сообщением Discord, а `error.problems` хранит их как объекты `SyncProblem`. Большинство проблем ловится раньше: декораторы проверяют имена, описания и лимиты при выполнении.
